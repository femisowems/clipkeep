## 2. Delay investigation — method and findings

Method: read the click/open code paths in `~/workspace/clipkeep-mac/main.swift` (6,604 lines at v2.18.0). No profiling on the Mac was done; findings are code-evidence, ranked by the amount of main-thread work on each path.

### F1 — Every panel open rebuilds the entire feed TWICE (main culprit)
- `togglePanel()` (line 6219) calls `refreshList()` synchronously before showing the panel, then calls it **again** inside the async post-show block.
- The second call is the v2.15.6 "first-show rebuild" workaround for a first-frame card-measurement bug (cards measured against frames that don't exist before the window is on screen; Femi's Nov 18, 2026 screenshot showed header bands pushed ~62pt down). The code comment at the call site admits that on later opens it is "an identical, invisible rebuild."
- `refreshList()` (line 4488) is a **full teardown/rebuild**: it removes every card view from `listStack` and re-creates all of them via `addRow`/`rowView` (lines 4634/4913) — view hierarchies, per-card text measurement (deterministic-height function, line ~4608), source-app icon lookups (`sourceAppIcon`, line 4749), plus `rebuildBoardPopup()`/`rebuildAppPopup()` and pill-badge recounts.
- At Femi's current history (89 clips), one open = ~178 card constructions on the main thread. `refreshList()` has **31 call sites**; it is the app's universal rebuild hammer.

### F2 — Every search keystroke is a full rebuild
- `controlTextDidChange` (line 3634) calls `refreshList()` directly — no debounce. Typing a 6-character search = 6 full rebuilds. Same pattern on tab/filter/sort changes (`filterChanged`, `sortChanged`). This is the lag felt on in-panel actions generally, not just panel open.

### F3 — The avatar toggle itself is cheap; its lag is perceptual + compositing
- `avatarClicked` (line 4221) → `setSyncView(open:)` (line 4189) → `applySyncBodyVisibility()` (line 4200) + `refreshSyncView()` (line 4111). Verified: no view rebuilds, no disk reads, no Keychain access on this path — only label/glyph updates and `isHidden` flips.
- Two remaining costs: (a) NSButton actions fire on mouse-**up**, so the press–release interval reads as lag; (b) the first display of the Sync view forces a compositing pass over the full-screen-width frosted panel (`NSVisualEffectView`, `.hudWindow`), which is the most expensive surface in the app to repaint.

### F4 — Cleared suspects (do not re-investigate)
- **Image decoding is NOT a current cost.** Since v2.12.0, `cardThumbnail(forFile:)` (line 4770) decodes each image file once, downsampled to 552px, and caches it in `thumbnailCache` keyed by filename (image files are write-once UUID names, so the cache cannot go stale; it clears only past 300 entries). Dimensions come from `CGImageSource` properties without decoding pixels. The remaining `NSImage(contentsOf:)` calls (lines 1856, 2654) are the Preview window and paste paths, where full fidelity is intended.
- **The ••• overflow menu** is constructed fresh on every click (`showOverflowMenu`, line 5464) but holds ~15 items — a few milliseconds at most. Not a factor.
- **The pasteboard poll** (0.5s timer, line 1663) does not touch the panel when nothing changed.

### F5 — Minor: the fixed panel frame can be applied twice per open
- `togglePanel` applies the frame synchronously, then re-applies it asynchronously if Stage Manager clamped it. Each `setFrame` on the screen-wide visual-effect window forces a full backdrop re-composite. Occasional, small; not separately patched (the F1 fix reduces total open cost around it).

## 3. "Skewered avatar" investigation — findings

The avatar button is square (32×32pt constraints, lines 3400–3401) with `chromeCornerRadius = 16` (line 3320) — the circle itself is true. The skew is an artifact of the status dot:

- `avatarDot` (lines 3325–3335) is an 8×8pt subview pinned at trailing −1 / bottom −1 **inside** the button. At the corner of a 32pt circle, the curve passes ~4.7pt in from the corner, so the dot straddles the circle's edge — half on the fill, half past the curve — which reads as a dent in the circle.
- Worse, the dot's border colour is `currentTheme.cardBG` (line 4186), but the button does not sit on a card — it sits on the panel's frosted backdrop. The mismatched ring renders as a pale crescent (visible in both of Femi's screenshots), and the signed-out dot colour (white 0.66, line 4184) on the grey fill (white 0.62, line 4166) has almost no contrast, so the dot mostly disappears into the crescent.
- The person glyph is configured at 13pt semibold (line 4172) in a 32pt button — small enough that the eye reads the disc first and the glyph second, which adds to the "off" impression.

## 4. The patch — 12 changes

Each item: what changes, where, why, and risk. All changes are in `main.swift` unless noted. The whole patch ships as one release (v2.18.1) under the standard pipeline (see §6).

### Delay fixes
- **P1 — Gate the second open-rebuild to the first open after launch.** In `togglePanel` (line 6219), run the async second `refreshList()` only when a new `hasShownPanelOnce` flag is false (the first-frame measurement bug it works around can only occur before the panel has real frames). Later opens do one rebuild instead of two. *Risk: low — the workaround stays exactly where the bug lives. If first-open cards ever render mis-measured again, this is the first suspect.*
- **P2 — Debounce search rebuilds.** In `controlTextDidChange` (line 3634), schedule the `refreshList()` ~120ms after the last keystroke, cancelling any pending one (the codebase already uses this pattern for history saves — see the comment at line 171). *Risk: trivial — worst case, results appear a beat after typing stops, which is the point.*
- **P3 — Avatar toggle on mouse-down + Sync view warm render.** Make the avatar button fire its action on mouse-down (`sendAction(on:)`), and run one offscreen layout/display pass of the Sync view when the panel is built/shown so its first real display is already composited; consider `shouldRasterize` on the sync container layer. *Risk: low — mouse-down firing is a feel change Femi asked for implicitly via the delay report; revert is one line.*

### Avatar & Sync polish
- **P4 — Status dot as a proper badge.** Grow 8→10pt, reposition so it straddles the button's edge cleanly as a badge instead of sitting inside the curve, and set its ring colour to the actual backdrop behind the search row (not `cardBG`). Signed-out state becomes a deliberate hollow/outline dot. Touches lines 3325–3335 and 4180–4187. *Fixes the §3 skew artifact and the Nov 23 legibility item.*
- **P5 — Glyph and signed-out fill.** Person glyph 13→15pt (line 4172); signed-out fill changes from flat grey (white 0.62, line 4166) to a warmer theme-tinted wash so the button reads as tappable, not disabled. Orange stays reserved for signed-in.
- **P6 — Esc chip consistency.** Restyle the Sync view's esc chip to match the keycap chips used in the panel's empty state (same radius, padding, weight).

### Audit fixes (Nov 24 audit of the v2.18.0 surfaces)
- **P7 — Open-state ring flicker.** `refreshAvatarButton` forces `layer?.borderWidth = 2` after `refreshChrome()` (lines 4174–4176), but `HoverButton.refreshChrome()` (lines 474–484) resets border width to 1 on every hover/press — so with the Sync view open, hovering the avatar visibly thins the blue ring. Fix: carry the border width in HoverButton's chrome state instead of overriding after the fact. *Risk: small — HoverButton is shared by other buttons; the change must default to current behaviour for them.*
- **P8 — Email fields made honest.** Both email fields (panel, lines 4045–4055; Settings, lines 5964–5975) are locals that are never read; `signInEmailClicked` (lines 4267–4270) ignores them, and `authorizeURL` has no `login_hint`. A typed address currently does nothing and the hosted page asks again. Fix: retain the field values, pass `login_hint` into the authorize URL, wire Return in the field to the same action as the button, and give the Settings field the panel field's 12.5pt font (line 4047). *Note: while accounts aren't live, the fields route to the "aren't live yet" alert like every other sign-in control — the fix makes them correct for the day the pool lands.*
- **P9 — Signed-in Sync card geometry.** The three card stacks are pinned leading/trailing/top only (lines 3988–3995) and `cardsRow` uses `alignment = .top` (lines 3999–4005), so cards end flush at their content with zero bottom padding and at uneven heights (Account ~7 rows vs Privacy ~3). The signed-out invite card pins all four sides (lines 4094–4099) — the signed-in cards should follow their own pattern: pin stack bottoms at −`spaceCardPad`, use `.fill` alignment for equal heights. *Latent until sign-in is live, but it's the surface's core geometry — cheaper to fix now.*
- **P10 — Social button feedback.** `socialButton` (lines 3778–3801) is a borderless NSButton with a layer background and no hover/pressed state; since the response (web sheet or alert) isn't instant, the primary sign-in controls feel dead for a beat. Add the same hover/pressed wash pattern the app uses elsewhere (HoverButton).
- **P11 — Tooltips & accessibility labels.** The avatar button (lines 3316–3323) and overflow button (lines 3291–3307) have no `toolTip` and no button-level accessibility label (VoiceOver gets an empty title; the signed-in avatar's "title" is a single initial). The update strip's ✕ (line 3366) is a bare glyph with neither. The app's own convention exists in `cardIconButton` (lines 4881–4908). Fix: "Account & Sync" / "More actions" / "Dismiss" tooltips + `setAccessibilityLabel`, state-aware on the avatar.
- **P12 — Consistency + dead-code sweep.** (a) Delete Account in Settings is a standard rounded button directly beside Sign Out (lines 6043–6050) while the panel treats it as borderless red text (lines 3936–3941) — match the panel's dangerous styling in Settings. (b) The Devices card dot is hard-coded `systemGreen` at build (lines 3950–3958) regardless of sync/auth state — drive it from the same state logic as the avatar dot (lines 4180–4187). (c) Tooltip on the permanently disabled Sync Now button ("Sync launches with ClipKeep Cloud"; the reason currently exists only in a code comment, lines 4146–4148). (d) Remove dead auth code: `AuthConfig.logoutEndpoint` (line 1009, never called — sign-out uses revoke, lines 1468–1482), `AuthConfig.region` (line 991, never referenced), `AuthSession.isExpired` (line 1174, never called), and merge the byte-identical `connectGoogleClicked`/`connectAppleClicked` duplicates of the sign-in handlers (lines 4257–4282). `sha256Hex` (line 1137) stays — tests.swift uses it.

## 5. Verification checklist (after shipping)

CI must pass all checks (75 at v2.18.0, plus any added). On Femi's Mac, on a fresh launch:

1. Open the panel — first open renders cards correctly (no pushed-down header bands — the v2.15.6 bug P1 must not regress).
2. Close and reopen several times — opens feel noticeably snappier than v2.18.0.
3. Type a search quickly — the feed settles once, ~a beat after the last keystroke, instead of rebuilding per character.
4. Click the avatar — the Sync view appears on mouse-down, no perceptible delay; hover the avatar while it's open — the blue ring stays 2pt, no flicker.
5. Avatar at arm's length: dot clearly visible as a badge, ring colour blends with the panel backdrop (no pale crescent), glyph reads as a person, button no longer looks skewed or disabled.
6. Esc chip in the Sync view matches the empty-state keycaps.
7. Settings → Account: Delete Account reads as dangerous; email field font matches the panel's.
8. Steps 26/27 behaviours unchanged: history intact, sign-in controls still show the "aren't live yet" alert, nothing else regressed.

Per the standing rule, the release is reported as **shipped, not fixed**, until Femi confirms on a fresh launch.

## 6. Rollback & release notes

- The patch ships through the standard pipeline: push via `push-files` → CI → download artifact → publish the **inner** `ClipKeep.zip` (with `ClipKeep.app/` at its root — never the raw artifact download) as `ClipKeep-app-v2.18.1.zip` → bump gist feed `114759138a0c643983d577960363096a` (both `latest` and `version` keys, `sha256` of the inner zip, revision 42 → 43) → update ROADMAP.md + App Roadmaps + MEMORY.md.
- The in-app installer keeps a backup of the previous bundle and rolls back automatically if the swap fails.
- If v2.18.1 misbehaves in a way the installer can't handle: the v2.18.0 release asset remains on GitHub (https://github.com/femisowems/clipkeep/releases/tag/v2.18.0) — re-pointing the feed's `url`/`sha256` back to it and bumping `revision` returns every updater to v2.18.0. Source-level, the patch is one commit and reverts cleanly with `git revert`.
- Highest-risk items if something looks wrong after shipping: **P1** (first-open card layout) and **P7** (shared HoverButton change). Check those first.
