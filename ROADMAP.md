## Codebase inspection — Nov 17, 2026 (at v2.6.0)

Requested by Femi. Method: full read of the local source plus static checks; compile verification is CI's job (no swiftc in Edison's VM) — CI run #24 is green for v2.6.0.

**Structure**
- Single-file app: `main.swift` — 3,322 lines / ~155 KB. `build.sh` (54 lines) compiles it with one `swiftc` call into ClipKeep.app (Cocoa, Carbon, ApplicationServices, Vision, UniformTypeIdentifiers), ad-hoc signed, minimum macOS 11.
- 12 types: `ClipItem` (Codable model), `ClipStore` (persistence), `PanelTheme`, six view/button classes (`HoverButton`, `PillTabButton`, `PillTabsView`, `ToolbarShell`, `FlippedView`/`FlippedStackView`, `ClickView`), and `AppController`.
- `AppController` is the monolith: lines 715–3315 (~2,600 of the file's ~100 methods), organized into 14 MARK sections — lifecycle, clipboard watching, Paste Stack, link previews, updates, Preview/edit, panel UI, frame persistence, themes, filtering/rendering, cards, actions, excluded apps, hotkeys.
- Data: `history.json` + `images/` in `~/Library/Application Support/ClipKeep`, with lossy per-clip decode so one corrupt clip can't kill the history (v2.2.1). Eight UserDefaults keys: theme, type filter, colour sort, Reduce Transparency, panel frame (V6), dismissed update version, update snooze, plus capture settings.
- Clipboard watch: a 0.5s Timer polling `NSPasteboard.changeCount`; concealed/transient pasteboard types are skipped.
- CI: GitHub Actions on macos-latest, build-only. Releases run a manual pipeline — CI artifact's sha256 verified locally before publishing, then the gist version feed is bumped.

**Health — good signs**
- Zero TODO / FIXME / HACK markers anywhere in the codebase.
- No `try!` or `as!` at all. The force-unwrap surface is small and conventional: 22 implicitly-unwrapped view properties (standard for programmatic AppKit), one `first!` on the Application Support URL, and four `fatalError`s in `init?(coder:)` boilerplate that are unreachable because every view is built in code.
- Every release since v2.2.0 was CI-verified with a matching sha256 digest before it was published.

**Changes reviewed (Nov 14–17)**
- 13 releases in four days, v2.0 → v2.6.0. The arc: card feed (v2.3.0) → polish and hotfixes (v2.3.1–v2.3.4) → button system (v2.4.0) → themes (v2.5.0) → copy/paste confirmation + hotfix (v2.5.1–v2.5.2) → update overhaul (v2.6.0).
- Two CI failures along the way, both fixed the same day: the v2.1.x launch crash, and v2.5.2's first run (a non-optional `attributedTitle` reset).
- One process bug with a lasting fix: the version feed's `"latest"` key was dropped in two gist bumps and silently broke update checks; the v2.6.0 parser now accepts `"latest"` or `"version"`.

**Risks / tech debt**
1. **No automated tests.** CI proves the app compiles; every behaviour check is manual, on Femi's Mac — the panel-frame and tab-rendering regressions were caught by his screenshots and Looms, not by tests. The pure-logic pieces (colour-literal parsing, hue sort, version comparison, frame validation) could be unit-tested without AppKit if extracted from AppController. **ADDRESSED in v2.14.0 (Nov 18):** the text/colour/store helpers were extracted to free functions and 36 checks now run in CI before every build ("ALL 36 CHECKS PASSED", run #54). What remains manual is UI behaviour — panel, flashes, clicks — which is what the confirmation checklist above is for.
2. **AppController monolith (~2,600 lines).** Panel, store glue, updater, preview, and menus share one class, so most edits are cross-cutting — where the recent bugs came from. The updater is self-contained since v2.6.0 and is the natural first extraction.
3. **Update trust chain.** The one-click installer downloads whatever the public gist's URL points at and swaps the bundle, with no checksum or signature check on the download. Fine for a personal app; adding the release's sha256 to the feed and verifying it before the swap is a small, high-value hardening. **CLOSED Nov 17 in v2.6.1:** the feed carries `sha256` and the installer verifies the download before unzipping or swapping; a mismatch aborts the install.
4. **Ad-hoc signing, not notarized.** First install needs Gatekeeper's "Open Anyway"; in-place bundle swaps keep the same path, so approvals persist.
5. **Housekeeping.** Nine release zips (~4.2 MB) sit in the source folder — local only, never pushed — and `.gitignore` doesn't cover them.
6. **CI dependency drift.** actions/checkout@v4 + upload-artifact@v4 draw a Node 20 deprecation warning (run #24); bump to v5 at leisure.

**Test status**
- Compile: CI green through run #25 (run #24 = v2.6.0; run #25 = the sizing-cleanup commit `c2967ac`, verified Nov 17).
- Behaviour: confirmed live by Femi through v2.5.1 (the Nov 17 screenshot showing clean tabs, full width, teal Link cards). v2.5.2's copy/paste confirmation and v2.6.0's strip + one-click install are shipped but not yet confirmed on his Mac — the one-click path gets its first real test on the next release.

**Sizing audit** *(added Nov 17 at Femi's request)*
Sizing is historically this app's #1 bug class — the strip bug (v2.1–v2.2), the 87%-width default (v2.3.2), the Stage Manager clamp (v2.5.1) — so it gets its own pass.

- **Panel window.** `minSize` 700×400, no maximum. The default frame is computed, not stored: full physical screen width × 520 tall, bottom-anchored to the visible frame (above the Dock); if no screen is available it falls back to 1100×520 centered. Since the Nov 17 cleanup (commit `84e7541`, staged for the next release), panel creation, frame restore, and Reset Panel Size all take that default from a single `defaultPanelFrame()` function — the app's built-in default IS the Reset size. Before that, the panel was created at 1100 wide in the corner and only became the full-width strip if the restore path ran.
- **Frame persistence is manual and validated** (key `ClipKeepPanelFrameV6`; the key has been bumped V3→V6, each bump retiring bad saved frames). A frame is only saved on resize/move if it passes `panelFrameIsUsable` (≥ minSize and intersecting some screen's visible frame); restore validates the same way, and `togglePanel` re-validates before every show. `windowDidResize` never calls `setFrame` — that loop is what crashed v2.1.0 on launch. The ••• menu's Reset Panel Size is the escape hatch: delete the saved frame, re-apply the default.
- **The 520 heuristic.** `normalizedPanelFrame` treats any frame with height ≈520 (±1pt) as the default strip shape and recomputes it to full screen width on both save and restore — this is what stops a Stage Manager clamp from being persisted. Deliberate trade-off: a user frame that is exactly 520 tall can never be narrower than full width; any other height is respected as custom.
- **Multi-monitor.** Validation accepts a frame intersecting any screen; normalization re-anchors to the first intersecting screen. No screen identity is stored, so if that display is unplugged the frame fails validation and the panel falls back to the main-screen default — graceful, if slightly surprising.
- **Cards and feed.** Cards are a fixed 300pt wide at natural height, top-aligned (header band 46pt, footer 28pt, action buttons 26×26, the "✓ Copied" chip 76×18). Card width does not adapt to panel width — at the 700pt minimum the panel shows about two cards. The scroll view carries fitting-size floors of 420×200, the v2.2.1 fix that ended the strip bug.
- **Controls.** Pill tabs 26pt tall, toolbar shells and filter bar 28pt, ••• button 30×30, update strip 34pt tall when open (0 when closed, with the tab-row gap toggling 0/8 via stored constraints), update progress bar 130pt wide.
- **Other windows.** Preview/edit is 580×520 (min 420×320, image area 300pt tall); Excluded Apps is 400×320. Neither persists its size.
- **Sizing risks.** (1) The default height `520` was hard-coded in at least four places — panel creation, the restore default, the no-screen fallback, and the normalization check. **Fixed Nov 17 (commit `c2967ac`, staged for the next release):** all four now use a single `defaultPanelHeight` constant. (2) The fixed 300pt card width is a design choice, not a bug, but it's the first thing to revisit if the panel ever needs a compact mode. (3) Preview and Excluded Apps windows don't remember their size/position between opens.

## Confirmation checklist — for Femi's next Mac session

Everything below shipped but has never been confirmed live. One pass (~10 minutes, ideally as a single Loom) closes the whole backlog. Written for v2.14.0, which includes the fixes the Nov 18 code audit found (the capture-path flash and the up-to-date flash were genuinely broken — see the v2.14.0 shipped-log entry).

**Launch & intro (v2.13.0/v2.14.0)**
1. Quit ClipKeep, then click its icon in the Apps grid → the panel opens and the launch intro plays once (icon, name, version; cards stagger in). Clicking the icon again while it runs also opens the panel.
2. Hide the panel and reopen with ⌘⇧V → no intro the second time; reopening is instant.

**Clicking & pasting (v2.12.0–v2.14.0)**
3. Single-click a card → it only selects (one outline, on that card). Double-click → it copies, the panel stays open, and the card chip + menu bar read "✓ Copied". Enter (or ⌘1) on the selected card → it pastes, fast (~¼ second), chip reads "✓ Pasted".
4. Settings → General → "Paste on single click" ON → a single click pastes. Turn it back OFF (or leave it how you like it — it's a preference now).

**Flashes (v2.5.2, repaired v2.14.0)**
5. With the panel closed, copy any text in another app → the menu-bar icon briefly flashes "✓ Copied" in green.
6. In the panel, right-click a card → Copy → the card flashes a "✓ Copied" chip.
7. Settings → Updates → "Check for Updates…" while up to date → the strip in the panel flashes "✓ You're up to date" for ~2 seconds.

**Keyboard (v2.9.0 — navigation itself confirmed Nov 18)**
8. Arrow to a card, press Enter → it pastes. Arrow to another, press Space → Preview opens (above the panel). Arrow to a throwaway clip, press ⌫ → it's deleted.

**Windows & lists (v2.12.0/v2.13.0)**
9. With the panel open, open Settings, Preview and Excluded Apps → each opens ABOVE the panel. In Excluded Apps (both places), the list starts at the top — add an app and remove it to be sure.
